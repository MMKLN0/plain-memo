# PlainMemo 2.1.1

## Improvements

- Improved mobile startup with count-based progressive loading. PlainMemo now displays the newest 25 memos first, fills the initial buffer to 50, and continues loading the remaining memos in the background.
- Limited background file-read concurrency and periodically yielded to the interface thread, reducing freezes while a large memo collection is being loaded.
- Paused background loading while the editor is open or Obsidian is in the background, and accelerated loading when scrolling reaches the current end or a feature needs the complete memo set.
- Reused in-progress and completed memo reads across card loading, search, and Time buoy queries to avoid reading and parsing the same file repeatedly.
- Made `plain_memo` the default scan and save folder for new installations. Existing user settings are not changed.

## Fixes

- Fixed desktop tag suggestions not refreshing immediately after text input or a Chinese IME composition was committed.
- Made desktop tag and WikiLink suggestions open above the cursor when there is not enough room below.
- Added stable filename-based ordering for progressive loading, including deterministic ordering for files created in the same minute and collision filenames such as `(2)` and `(3)`.

## 改进

- 优化手机端启动时的大量笔记加载：先显示最新 25 篇，再补齐到 50 篇作为首屏滚动缓冲，其余笔记在后台继续加载。
- 限制后台文件读取的并发数量，并按处理时间主动让出界面线程，减少加载大量笔记时的卡顿。
- 编辑器打开或 Obsidian 进入后台时暂停后台加载；滚动到当前末尾或某项功能需要完整笔记集合时，会加快剩余内容的加载。
- 卡片、搜索和时光浮标会复用正在进行及已经完成的笔记读取结果，避免重复读取和解析同一个文件。
- 新安装用户的默认扫描与新建笔记目录改为 `plain_memo`，不会修改现有用户已经保存的设置。

## 修复

- 修复电脑端输入文字或确认中文输入法候选词后，标签自动补全不能立即刷新的问题。
- 当光标下方空间不足时，电脑端标签与 Obsidian 内部链接建议会改为显示在光标上方。
- 为渐进加载增加稳定的文件名排序；同一分钟创建的文件以及带 `(2)`、`(3)` 等冲突编号的文件也会保持确定的显示顺序。
